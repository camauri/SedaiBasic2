SedaiBasic · demo

A voxel landscape, written in BASIC

No polygons, no depth buffer, no matrix. A heightmap drawn one screen column at a time, front to back, with an occlusion line that only ever rises — the whole renderer is two nested loops and a comparison. It compiles to a 19 KB WebAssembly module.

How it draws

For each column of the screen the renderer walks outwards from the camera along one ray, sampling the heightmap at increasing distance. Each sample projects to a height on the screen; a single number per column remembers how high that column has already been filled, and a sample that does not reach above it is discarded without drawing anything. Because the walk goes from near to far, that number only ever rises — so a ridge close to the camera silently hides everything behind it, and nothing is ever drawn twice.

That is the entire hidden-surface algorithm: one comparison per sample, no depth buffer, no sorting, no polygons. It is what voxel-space renderers did on machines that had none of those, and it is still the reason this runs in real time in a browser.

What the terrain is made of

Value noise at several frequencies gives the heights. The colours come from altitude bands, and the sun is cast once, before the first frame, into a shadow map. Neither of those costs anything per frame: both fold into a colormap that is built at startup and then only read.

The fog is the one enrichment that depends on where the camera is, and it is about a millisecond of a 640×480 frame — which is why it is the only one that had to be measured before it was kept.

In the browser

sbc --target wasm compiles the same source to a module the page carries inside itself. The offline mode — the one that writes raw frames to a file for encoding into video — excludes itself here with no special case at all: a module has no filesystem, so the compiler refuses the opcode rather than emit something that runs and lies, and the branch is simply absent from the build. Writing 3.7 GB of raw frames from a browser tab was never going to be the point.

⚠️ This page replaces an earlier one that had two faults worth naming, because both are invisible until they are not. It compiled the module synchronously, which a browser refuses for any buffer over 4 KB on the main thread — it ran on the desktop it was written on and would have failed on a phone. And it never rebuilt its view of the module's memory: a typed array over that memory is detached the moment the memory grows, its length becomes zero, no exception is raised, and the canvas freezes on its last frame while every counter goes on rising.

What it costs

640×480 framemilliseconds
render, WebAssembly under Node8.7
blit to the canvas1.3

The blit is a word at a time rather than four bytes: a framebuffer word is 0xAARRGGBB and ImageData wants the bytes the other way round, so the swap is two shifts and a mask per pixel instead of four loads and four stores. Measured at this size, that took the blit from 6.2 ms to under 2. And a straight copy — no swap at all — renders a blue sky orange, which no numeric test can catch, because the pixel values are right either way.
