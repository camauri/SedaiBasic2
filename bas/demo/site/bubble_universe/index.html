SedaiBasic · demo

Bubble Universe, written in BASIC

Sixty-two thousand five hundred points a frame, each one placed by a pair of phasors fed back from the point before it. Nothing is stored between frames. It compiles to a 9 KB WebAssembly module that runs in the browser with nothing to install.

There is no animated preview on this page on purpose: the thing itself is one click away and it moves at sixty frames a second. A film of it would have been a megabyte and a half of worse.

What you are looking at

Despite the name there are no bubbles and no physics. 250 spirals are traced at once. Each spiral walks 250 points, and every point is the sum of two unit-length phasors — points on the unit circle — whose phases are fed back from the point produced immediately before it.

Z  = e^(j·a) + e^(j·b)        so  Re Z = cos a + cos b,  Im Z = sin a + sin b
plot Z
a := col + K · Re Z           re-modulate the CARRIERS,
b := phi + K · Im Z           not the previous phases

That feedback is the entire effect. Without it, two phasors with phases advancing linearly draw two circles and nothing else. With it, each point displaces the phases that generate the next one, the trace winds into a spiral whose curvature varies along its own length, and 250 of them from evenly spaced start phases interleave into the figure.

The one line most likely to be mistranslated. Both updates start again from the spiral's fixed constants: the point only perturbs them. Written a := a + K·Re Z instead, the phases drift without bound, the figure loses its 250-fold symmetry within a few dozen steps and then diverges. It does not fail loudly — it fails by slowly becoming noise, which is the hardest kind of wrong to notice.

Why it runs in real time

Not because it does little arithmetic: it makes four transcendental calls per point, 250,000 a frame. It is the working set. A spiral carries exactly two numbers from one step to the next, so the live state of the whole figure is 500 doubles — four kilobytes at 250 spirals, which sits in the first-level cache and never leaves it. The figure is redrawn from scratch every frame and nothing is stored between them.

A second consequence of the mathematics pays for itself in the plotting: each phasor has length exactly 1, so their sum cannot exceed 2. The whole universe lives inside a disc of radius 2, and the plotting needs no clipping test at all.

In the browser

sbc --target wasm compiles the same source to a module the page carries inside itself. Four things are compiled out of that build and each has a reason: the frame dump (a module has no filesystem, and the compiler says so rather than emitting something that runs and lies), the screen lock (there is no presenter to hold back), the on-screen frame counter (in a browser the frame rate is the page's to measure, and the page owns the clock the frames arrive on), and the loop itself — a module that ran until a key was pressed would freeze the tab.

And the phase comes from the frame number, not from the clock. Natively it advances by real elapsed time, which is right on a screen — the figure turns at one speed whatever the frame rate — and wrong on a page anyone can open, where it would make the animation depend on how fast your machine happens to be. Counted in frames, everyone sees the same thing.

Checked, not asserted: the module draws the frame sb draws for the same phase, byte for byte — at two phases, because at the first frame the phase is zero whatever formula produced it, so a wrong one still draws the right first frame.

This demo does not separate the engines, and that is the interesting part

SedaiBasic runs the same file with a bytecode interpreter, with a JIT that compiles hot loops while it runs, or with an AOT compiler that compiles whole functions before it starts. On some programs that is worth ten times. Here, measured over 300 frames at 500×500:

engineframes per secondms a frameagainst the interpreter
bytecode interpreter2753.6—
JIT2494.00.9×
WebAssembly (Node)3432.91.2×
AOT3662.71.3×

Four transcendental calls per point dominate everything else, and every engine hands those to the same library — so there is very little left for a compiler to win. What an engine buys you is a fact about your program, not about the engine, and a demo that says so is worth as much as one that shows a tenfold gap.

⚠️ The JIT being slower than the interpreter here is not a fact of life, it is a defect, and it is logged as one. Reproducible across runs, about 10%.

None of the mathematics is ours. The algorithm is yuruyura's, posted in February 2020; Paul Dunn ported it to BASIC and gave it the name; Mike Markowski rewrote it in Python using complex phasors with an explicit feedback term, and this follows his formulation — verified identical to spirals.py, pixel for pixel. What is ours is the translation into SedaiBasic, the tabulated palette and the real-time loop.
